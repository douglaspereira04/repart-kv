# Repart-KV

Repart-KV is a C++20 project that executes key-value workloads against a partitioned storage layer. It supports multiple storage backends and can repartition based on observed access patterns using METIS.

Workloads are generated by [LoadGen](https://github.com/douglaspereira04/loadgen) from a TOML config (the bundled `ycsb_*.toml` files). LoadGen is fetched automatically at configure time.

## Build

### Using the build script

`build.sh` configures CMake, builds the core library + tests, and runs `run_tests.sh` by default. Pass `-t`/`--runner` to also build the optional CLI (`repart-kv-runner`).

```bash
./build.sh           # builds repart-kv-core + tests
./build.sh -t        # also builds repart-kv-runner
```

### Manual build

```bash
mkdir -p build
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_REPART_KV_RUNNER=ON
cmake --build build -j"$(nproc)"
```

## Run workloads

The CLI runner is optional (`repart-kv-runner`). Either build it via `./build.sh -t` or set `-DBUILD_REPART_KV_RUNNER=ON` when configuring CMake.

```bash
cd build
./repart-kv-runner <loadgen_config.toml> [partition_count] [test_workers] [storage_type] [storage_engine] [thinking_time_ns] [storage_paths] [repartition_interval_ms] [max_duration_s] [sync] [tracking_duration_ms]
```

### Arguments

- **loadgen_config.toml**: path to a LoadGen TOML file (required). Bundled examples: `ycsb_a.toml` … `ycsb_e.toml`.
- **partition_count**: number of partitions (default: `4`)
- **test_workers**: worker threads for workload execution (default: `1`)
- **storage_type**: `hard`, `soft`, `threaded`, `hard_threaded`, `engine`, `lock_stripping`, or `range_lock_stripping` (default: `soft`)
- **storage_engine**: `tkrzw_tree`, `tkrzw_hash`, `lmdb`, `lmdb_nolock`, `tokyo`, `leveldb`, `rocksdb`, `map`, or `tbb` (default: `tkrzw_tree`). Caller-owned sync (pair with kvstorage RW locks): `lmdb_nolock`, `tokyo`.
- **thinking_time_ns**: per-operation delay in nanoseconds (default: `0`)
- **storage_paths**: comma-separated directories used for embedded DB files (default: `/tmp`)
- **repartition_interval_ms**: interval between repartitioning cycles (default: `5000`). Does **not** change tracking duration.
- **max_duration_s**: wall-clock cap for the operation phase in seconds (default: `20`)
- **sync**: engine durability sync: `true`/`false` or `1`/`0` (default: `false`)
- **tracking_duration_ms**: how long to track accesses before a repartition (default: `100`)

The bundled `ycsb_a.toml` … `ycsb_e.toml` configs load **1M records with the 1 KiB default value** (`gen_values = false`), about **1 GiB** of payload — small enough to sit in the page cache on a 32 GiB machine. `ycsb_a_large.toml` / `ycsb_d_large.toml` / `ycsb_e_large.toml` use the same mixes with **8,388,608 records × 4096 B = 32 GiB** of values (`gen_values = true`); run them with `experiment_set_large.sh`. The operation phase still stops at `max_duration_s`.

### Examples

```bash
# Defaults: 4 partitions, 1 worker, soft + tkrzw_tree, /tmp
./repart-kv-runner ../ycsb_c.toml

# 8 partitions, 4 workers, threaded storage, tbb backend (in-memory)
./repart-kv-runner ../ycsb_a.toml 8 4 threaded tbb

# Persistent backend, thinking time 0, two storage directories
./repart-kv-runner ../ycsb_a.toml 8 4 soft tkrzw_tree 0 /mnt/d1,/mnt/d2
```

## Workload format

The runner does **not** read CSV workload files. It constructs a LoadGen `RequestGenerator` from the TOML config. That generator has a **LOADING** phase (`n_records`) followed by an **OPERATIONS** phase (`n_operations` per worker).

Typical knobs in the bundled configs:

```toml
workload.n_records = 1000000
workload.n_operations = 10000000
workload.data_distribution = "ZIPFIAN"
workload.read_proportion = 0.5
workload.update_proportion = 0.5
workload.scan_proportion = 0.0
workload.insert_proportion = 0.0
```

Writes that do not carry a generated value use a default 1KB payload (`workload::DEFAULT_VALUE` in `workload/Workload.h`). `Workload.h` still contains an unused CSV parser (`0,<key>` / `1,<key>` / `2,<key>,<limit>`); the runner never calls it.

## Output

Runs write two CSVs in the current working directory (usually `build/`):

1. **Time series**, named from the run parameters:

   `{workload}__{workers}__{type}__{partitions}__{engine}__{path_count}__{repartition_ms}__{thinking_ns}__{sync_on|sync_off}.csv`

   ```csv
   elapsed_time_ms,executed_count,memory_kb,disk_kb,Tracking,Repartitioning
   0,0,4084,45244,x,x
   1002,11,4380,45244,o,x
   ```

   `Tracking` / `Repartitioning` are `o` or `x` (on / off). They stay `x` for `engine`, `lock_stripping`, and `range_lock_stripping`.

2. **Latency**, same stem with `.csv` replaced by `__latency.csv` (`start_ns,end_ns`, relative to experiment start).

## Linking against the library

`repart-kv-core` is a static library that exports `run_repart_kv(argc, argv)` from `src/repart_kv_api.h`. The library already publishes the repository root as a public include directory.

```cmake
add_subdirectory(/path/to/repart-kv)
target_link_libraries(my_binary PRIVATE repart-kv-core)
```

```cpp
#include "src/repart_kv_api.h"
```

`run_repart_kv(argc, argv)` mirrors the CLI argument validation described above. Wire new engines and storage types in `src/repart_kv.cpp`, not in `main.cpp`.

## Dependencies (summary)

See [INSTALL_DEPENDENCIES.md](INSTALL_DEPENDENCIES.md) for full instructions.

- **Required**: CMake ≥ 3.20, C++20 compiler, `pkg-config`, TKRZW, Abseil
- **Fetched at configure time**: LoadGen, `unordered_dense`
- **Needed for repartitioning**: METIS
- **Used for specific backends/features**: LMDB, Tokyo Cabinet, LevelDB, RocksDB, Intel TBB, Boost Lockfree (threaded workers)
- **Build script convenience**: `clang-format` (used by `build.sh`)

## Extending: adding a new storage engine backend

Implement the `StorageEngine` interface (`storage/StorageEngine.h`) and wire it into CMake plus `src/repart_kv.cpp`.

For the concrete steps, see **“Extending: adding a StorageEngine backend”** in [ARCHITECTURE.md](ARCHITECTURE.md).

## Repository layout

```text
repart-kv/
  src/          Core executor (`run_repart_kv`)
  graph/        Graph + METIS adapter
  keystorage/   KeyStorage abstractions and implementations
  kvstorage/    Partitioned and (re)partitioning storage layers
  storage/      StorageEngine backends
  workload/     Shared workload helpers (default write value)
  utils/        Shared test utilities
  ycsb_*.toml           LoadGen workload configs (use *_large.toml for 32 GiB)
  experiment_set.sh     Experiment grid (1 GiB YCSB configs)
  experiment_set_large.sh  Same grid with *_large.toml
  main.cpp              Thin CLI trampoline for repart-kv-runner
  build.sh              Configure/build/test script
  run_tests.sh          Test runner for build artifacts
```
